# Полевые тесты MTU Guard 0.3

## Зафиксированная приёмка 22.11.2026

Основной автоматический режим 0.3.0 — **Windows 11 x64 VERIFIED / PASS** на двух пользовательских ПК: установка/автостарт, коррекция MTU 1376 → 1280, переподключения и перезапуск AmneziaVPN, смена раздельного туннелирования и reboot. Зарубежный HTTPS после установки подтверждён на основном ПК. На втором ПК часть запросов была до установки, а самопроизвольная коррекция клиентом выделена отдельно.

[Полный протокол и ограничения](FIELD_ACCEPTANCE_WINDOWS11_2026-11-22.md). Windows 10 x64 — **EXPERIMENTAL**, ручной режим — **TEST CANDIDATE**. T23 подтверждён для выполненных переключений Windows 11; это не доказывает новый LUID на каждом переходе. T24 (чистые ОС), числовые имена/неоднозначность T29–T34, час нагрузки и полная внешняя приёмка ручного режима остаются отдельными проверками. Ниже сохранены команды для воспроизведения и расширения матрицы.

Пакет предназначен для Windows 10/11 x64, начиная с Windows 10 1809. Он не требует Rust, SDK, VC++ Redistributable или отдельно устанавливаемого .NET Runtime. Установка использует штатный Windows PowerShell 5.1.

Испытания выполняйте на подходящем тестовом ПК: переключение VPN, завершение AmneziaVPN и перезагрузка могут прервать текущие соединения. Не передавайте конфигурации, ключи или токены. Текущий кандидат не подписан Authenticode; при блокировке Smart App Control сообщите издателю и остановите этот сценарий. Отключать защиту или устанавливать VC++ Runtime для «исправления» теста не нужно.

## 1. Подготовить пакет

Сверьте SHA-256 ZIP с `RELEASE_SHA256SUMS.txt` от издателя и распакуйте архив целиком. Из распакованной папки откройте PowerShell:

```powershell
Get-FileHash .\MTU-Guard-0.3.0-win-x64.zip -Algorithm SHA256
```

Эта команда выполняется в папке с ZIP перед распаковкой. После распаковки проверьте внутренние записи:

```powershell
Get-Content .\SHA256SUMS.txt | ForEach-Object {
    $expectedHash, $relativePath = $_ -split '  ', 2
    $actualHash = (Get-FileHash -LiteralPath (Join-Path $PWD $relativePath) -Algorithm SHA256).Hash.ToLowerInvariant()
    if ($actualHash -cne $expectedHash) { throw "SHA-256 mismatch: $relativePath" }
}
```

## 2. Чистая Windows без среды разработки (T24)

На чистой Windows 10 и отдельно на чистой Windows 11, без установки VC++ Redist, выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\clean-runtime.ps1 -RequireCleanMachine -OutputPath .\evidence\runtime.json
```

Скрипт проверит импорты DLL, версию, справку, `status` и `check`. При выключенной VPN допустим `check=3`. При существующем неправильном MTU допустим `check=4`: это диагностика, она сеть не меняет.

Если найдены зарегистрированные VC++ Runtime или инструменты разработки, скрипт сохранит данные, но завершит строгую проверку ошибкой: такой ПК не подтверждает чистое окружение. Это не ошибка автономного EXE. Отдельно запишите точные версии ОС и AmneziaVPN; при необходимости приложите сведения о происхождении чистого образа.

## 3. Установка, обновление, остановка и удаление (T27)

На ПК без существующей установки MTU Guard откройте **64-битный Windows PowerShell от администратора**:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\windows-integration.ps1 -OutputPath .\evidence\scm.json
```

Тест временно создаст службу, проверит кавычки в Program Files, Auto/LocalSystem, ACL, stop/start, повторную установку поверх работающей 0.3 и удаление. В конце удалит свои службу и файлы. При существующей установке/логах тест откажется продолжать, чтобы не затронуть их. Это проверка повторной установки текущей версии; переход с ранее установленной 0.1 отмечается отдельным ручным тестом.

Затем проверьте обычный пользовательский путь: двойной клик `install.cmd`, один запрос UAC, запуск службы. Установщик сообщает о службе отдельно от MTU: без интерфейса выдаётся WAITING, при неправильном MTU ожидается 1280 до 15 секунд, а затем — ошибка, если исправления нет.

## 4. Split tunneling и пересоздание (T23)

После установки подключите тестовый профиль AmneziaVPN. Оставьте профиль неизменным и запустите сбор наблюдений:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\collect-evidence.ps1 -DurationSeconds 180 -ProbeHttps -OutputPath .\evidence\split.jsonl
```

Пока окно собирает данные, вручную переключите split tunneling **off → on → off**. После каждого изменения дождитесь устойчивого соединения. Отметьте время действий и фактическую работу Telegram/Discord. Скрипт читает фактическое имя, MTU, LUID, ifIndex и состояние службы; HTTPS-проба работает асинхронно через встроенный HTTP-клиент PowerShell, без внешнего curl, прокси и перенаправлений. Сохраняются только HTTP-код и код завершения, не содержимое ответа с публичным IP. Результат HTTPS появляется в записи после завершения запроса и не блокирует опрос интерфейса.

Ожидается: во время удаления адаптера WAITING; после появления нужного alias — новый актуальный LUID и MTU 1280. Разрешены `AmneziaVPN` и `AmneziaVPN N` (N от 1 до 4294967295, без знака и ведущих нулей). Up, нефизический интерфейс и строка IPv4 обязательны. Произвольное переименование не поддерживается; `status` покажет кандидатов. Нельзя обещать мгновенную коррекцию: окно событий 400 мс, верификация после записи 350 мс, резервная проверка 30 секунд.

Если исходный MTU уже 1280, отметьте это: такой тест подтверждает сопровождение пересоздания, но не доказывает исправление 1376 → 1280. На отдельном согласованном стенде потребуется воспроизвести реальный неправильный MTU.

## Числовые имена и несколько кандидатов (T29–T34)

На отдельном стенде с естественно возникшим числовым именем выполните `status.cmd` и запустите сборщик из раздела 4. Не переименовывайте рабочий адаптер и не удаляйте драйверы ради теста.

- Для единственного подходящего `AmneziaVPN 1`, `AmneziaVPN 2` или другого допустимого N статус, лог и `adapter_alias` в JSONL должны содержать именно его имя; IPv4 MTU должен стать 1280.
- Старый Down/отсутствующий IPv4-экземпляр не должен мешать единственному подходящему Up+IPv4-интерфейсу.
- Если на согласованном стенде одновременно есть два подходящих Up+IPv4-интерфейса, ожидается `[FAIL] AMBIGUOUS`, `status`/`check` возвращают 1 и служба ничего не меняет. Не выбирается ни базовое имя, ни наибольший номер. Сборщик продолжает запись, сохраняет `status_exit=1` и текст ошибки; поля выбранного адаптера — null.
- При отсутствии подходящих интерфейсов ожидается WAITING; `status=0`, `check=3`. При WAITING MTU не заявляется как исправленный.
- Имена `AmneziaVPN +2`, `AmneziaVPN 02`, `AmneziaVPN Backup`, `AmneziaWG`, Ethernet/Wi-Fi и физический интерфейс с разрешённым именем не должны выбираться. Описание и тип устройства в диагностике помогают разобраться, но не являются подтверждением принадлежности драйвера.

Модельные тесты автоматически проверяют также появление второго кандидата, смену LUID, состояния, потерю IPv4 и ошибки API между чтением и записью. Для реального переключения split tunneling применяется раздел 4; модель не заменяет этот полевой сценарий. Пауза между последней проверкой и системной записью полностью не устраняется.

## 5. Перезапуск клиента, холодный старт, час нагрузки (T26/T28)

На тестовом ПК проверьте полный выход из AmneziaVPN, повторный запуск, завершение её процесса через диспетчер задач и холодную загрузку Windows. Убедитесь, что служба запускается раньше VPN и переходит WAITING → актуальный интерфейс → 1280. Сохраните времена действий и фрагмент `%ProgramData%\WITHEN\MTU Guard\guard.log`.

Для часа наблюдений:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\collect-evidence.ps1 -DurationSeconds 3600 -IntervalMilliseconds 30000 -OutputPath .\evidence\idle-hour.jsonl
```

`cpu_seconds` — накопленное CPU-время службы. `cpu_percent_one_core` вычисляется по разности соседних отсчётов: 100% соответствует одному логическому процессору. При смене PID сравнение сбрасывается. Working set/private bytes — память процесса службы. Сборщик сам запускает диагностический CLI; его нагрузка не входит в CPU службы.

Наблюдайте память, ошибки и число реальных коррекций по `guard.log`; отсутствие записей при уже верном MTU соответствует ожидаемому поведению. Короткая выборка или нулевой delta CPU не доказывают буквальную нулевую нагрузку.

## 6. Что вернуть издателю

- `runtime.json` и точные версии Windows/AmneziaVPN.
- `scm.json` и `scm.json.guard.log`, если SCM-тест выполнен.
- `split.jsonl`, `idle-hour.jsonl`, времена ручных переключений/перезапуска и наблюдения Telegram/Discord.
- Небольшой относящийся к тесту фрагмент `guard.log`; перед отправкой просмотрите файлы.
- SHA-256 полученного ZIP и статусы нужных Txx из [TESTING.md](TESTING.md). Не проставляйте PASS для невыполненного сценария.

Для удаления после полевых тестов запустите `uninstall.cmd`. Удаление службы не меняет MTU адаптера.

## Ручной инструмент 0.1 — T35–T39

Это отдельный кандидат из `scripts/package-manual.ps1`, добавленный после ZIP службы 0.3. Полная инструкция: [MANUAL_MTU](MANUAL_MTU.md).

- T35: `manual-check.cmd` без VPN — WAITING/код 3, с единственным подходящим интерфейсом — его фактический MTU. UAC и записи отсутствуют.
- T36: на согласованном стенде с MTU 1376 выбрать меню 2 и подтвердить UAC; ожидаются 1280 и повторная проверка той же цели. HTTPS проверить отдельно. Отмена UAC не считается успехом.
- T37: старый Down и активный `AmneziaVPN 1`/`2` — выбирается только подходящий активный экземпляр.
- T38: два подходящих активных IPv4-интерфейса — AMBIGUOUS, код 1, запись запрещена. Ошибка API также прекращает выбор.
- T39: согласованный тест нестандартного MTU 1200 и возврат к 1280. Работающая служба будет восстанавливать 1280, поэтому сценарий выполняют на подходящем стенде. Инструмент не останавливает службу и не управляет VPN.

Реально на текущем ПК проверены Check и Fix при уже правильном 1280, без записи/UAC. Реальная запись, числовые имена и чистая Windows 10 — NOT RUN. Read-only сопоставление при необходимости: `netsh interface ipv4 show subinterfaces` и `withen-mtu-guard.exe status` из отдельного пакета службы.
