# MTU Guard 0.3.0 — полевая приёмка Windows 10 x64

**Дата:** 23 ноября 2026 г.\
**Проект:** [MTU Guard](https://github.com/flamy-studio/mtu-guard)\
**Релиз:** [`v0.3.0`](https://github.com/flamy-studio/mtu-guard/releases/tag/v0.3.0)\
**Исполнитель / издатель:** Flamy Studio; применение в WITHEN Network\
**Лицензия:** Apache-2.0\
**Объекты:** нативная служба Windows `WithenMtuGuard` 0.3.0 (Rust); ручной PowerShell-инструмент 0.1\
**Тестовая среда:** Windows 10 x64, сборка **19045**, Windows PowerShell **5.1.19041.6456**, AmneziaVPN / AmneziaWG 3.1, `WITHEN_HUB`.\
**Тип доказательств:** пользовательские фотографии и вывод команд, файл PowerShell transcript, фрагмент лога службы, отдельное сообщение тестировщика о выполненном пункте 2 ручного инструмента. Это полевая, а не независимая лабораторная или сертификационная проверка.

## 1. Решение

**Windows 10 x64 / основной автоматический режим 0.3.0 — VERIFIED / PASS для испытанной конфигурации.**

Служба успешно установилась и функционировала на пользовательской Windows 10 без средств разработки. Реальная коррекция IPv4 MTU **1376 → 1280** подтверждена внутренним журналом с повторной проверкой результата. Подтверждены состояние `RUNNING`, внешний HTTPS через используемый WRE Exit, устойчивое восстановление после повторного появления VPN-адаптера и длительная работа одного экземпляра процесса приблизительно **3 ч 59 мин** до контрольного отчёта. В наблюдавшихся данных нет признаков критического сбоя службы.

**Ручной режим 0.1 — BASIC FIELD PASS (self-reported).** Тестировщик сообщил, что запустил `manual-mtu.cmd`, выбрал пункт **2** (установка MTU 1280) и получил успешный результат. Это выполненный реальный пользовательский тест, а **не** `NOT RUN`. Отдельный машинный протокол именно этого запуска не приложен; поэтому расширенные проверки ручного режима остаются открытыми.

**Вердикт ограничен испытанным сценарием:** результат не равен гарантии для всех сборок Windows 10, всех VPN-конфигураций, всех числовых имён и случаев нескольких активных адаптеров.

## 3. Проверяемые выдержки из журналов

### 3.1 Автоматическая коррекция

Фрагменты журнала службы, показанные пользователем (время сохранено как `unix_ms`):

```text
unix_ms=1795445997503 [INFO] MTU Guard started
unix_ms=1795445997855 [PASS] AmneziaVPN MTU 1376 -> 1280; verified; LUID=0x0035008000000000 ifIndex=3 correction_ms=352; description="WireGuard Tunnel" type=53
unix_ms=1795446320063 [PASS] AmneziaVPN MTU 1376 -> 1280; verified; LUID=0x0035008000000000 ifIndex=3 correction_ms=352; description="WireGuard Tunnel" type=53
unix_ms=1795446390593 [WAITING] no eligible active virtual IPv4 adapter (AmneziaVPN or AmneziaVPN N); connect the VPN and inspect candidate diagnostics
unix_ms=1795446531747 [PASS] AmneziaVPN MTU 1376 -> 1280; verified; LUID=0x0035008000000000 ifIndex=3 correction_ms=352; description="WireGuard Tunnel" type=53
```

Обозначение `correction_ms=352` — длительность **конкретной операции с проверкой**, не гарантированная верхняя граница времени восстановления после любого события Windows. Повторные `started`/`stopped` происходили во время проверки жизненного цикла; после запуска текущего экземпляра в 18:07 дальнейшей остановки по представленным данным нет.

### 3.2 Состояние на контрольном срезе

Файл `MTU_Guard_Test.txt`, 23.11.2026, **22:06:25–22:06:26**:

```text
SERVICE_NAME: WithenMtuGuard
STATE              : 4  RUNNING
WIN32_EXIT_CODE    : 0  (0x0)
SERVICE_EXIT_CODE  : 0  (0x0)

MTU  ... Interface
1280 ... AmneziaVPN
1500 ... Ethernet
1500 ... Ethernet 2
```

Отдельная проверка CIM:

```text
Process: withen-mtu-guard.exe
CreationDate: 23.11.2026 18:07:01
ProcessId: 3772
CPU: 0.09375 seconds (cumulative)
WorkingSet64: 1327104 bytes (~1.27 MiB)
```

Отсчёт от `CreationDate` до указанного контрольного transcript составляет **3 ч 59 мин 24 с**. Показатель CPU — **накопленный**, а не процент загрузки; RAM — **один снимок**, а не зарегистрированный максимум за всё время.

### 3.3 Подтверждение передачи трафика

В PowerShell получен ответ `HTTP 200 OK` от `https://1.1.1.1/cdn-cgi/trace`. В ответе присутствует публичный выходной IP `45.80.228.141`, соответствующий использовавшемуся WRE Exit. Этот тест подтверждает успешный HTTPS именно в испытанной конфигурации; он не гарантирует работу каждого стороннего приложения.

### 3.4 Ручной инструмент — статус доказательства

Со слов участника: `manual-mtu.cmd` запущен, выбран пункт меню **2**, применение `MTU=1280` завершилось успешно. Порядок значений в этом пункте подтверждён исходным `docs/MANUAL_MTU.md` и содержимым пакета 0.3. **Засчитан реальный базовый сценарий ручного инструмента (PASS reported)**. Действие ручного инструмента нельзя автоматически приписывать автоматической службе: оба механизма испытывались в разных фазах.

В связи с отсутствием отдельного консольного протокола ручного запуска не заявляются пройденными проверка отмены UAC, произвольный MTU, обработка двух активных интерфейсов и гарантированное отсутствие побочных изменений.

## 4. Ресурсы, ошибки и безопасность

- В наблюдаемом контрольном срезе Windows Service работала с кодами завершения `0`, настройка Ethernet сохранялась на `MTU=1500`.
- В предоставленном фрагменте `guard.log` нет записей `[FAIL]` или критического завершения процесса. **Это не эквивалент полного анализа всех записей журнала.**
- При отсутствии адаптера статус `WAITING` — штатный сценарий, не ошибка.
- Выполненное исправление требует административных полномочий, которые предоставляет установщик службы; нельзя считать `RUNNING` отдельным доказательством безопасности всего ПО.
- ZIP публичной версии не подписан Authenticode. Политики Defender/SmartScreen не отключались ради испытаний.
- В публичный отчёт намеренно не включены локальные учётные имена, рабочие пути и изображения рабочего стола тестировщика. Исходные доказательства сохранены у команды проекта.

## 5. Заключение и критерии совместимости

**Принято решение повысить статус основной службы MTU Guard 0.3.0 для Windows 10 x64 с `Experimental` до `Verified (field-tested)`** — на основании испытаний Windows 10 build 19045. Для Windows 11 x64 сохраняется ранее установленный статус `Verified` по отдельному [отчёту Windows 11](FIELD_ACCEPTANCE_WINDOWS11_2026-11-22.md).

**Ручной инструмент 0.1:** основной сценарий меню 2 пройден пользователем на Windows 10; статус **Basic field-tested**, но **не Full-verified** по расширенному набору. Это не препятствует выпуску основной службы, если в документации честно указаны ограничения ручного режима.

**Остаточные тесты** — не блокируют подтверждённую работоспособность стандартного автоматического режима, но должны оставаться открытыми в `docs/FIELD_TESTS.md`: реальный `AmneziaVPN N`, неоднозначность с двумя одновременно активными интерфейсами, исключения UAC, нестандартное значение MTU, отдельный протокол uninstall, строгая «чистая» Windows, повторное испытание ручной утилиты на Windows 11 и нагрузочный тест с временным рядом CPU/RAM (в отличие от снимка).
