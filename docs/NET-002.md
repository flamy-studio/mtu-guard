# NET-002 — числовые имена и выбор адаптера

Реализовано в MTU Guard 0.3. Разработчик и издатель: [Flamy Studio](https://flamy.studio). Заказчик: [Withen Network](https://withen.pro). Дата проверки источников: 22.11.2026.

## Основание

В Wintun 0.14.1 обработка конфликта имени в `NciSetAdapterName` перебирает числовые суффиксы начиная с **1**; может переименовываться прежний экземпляр. Это подтверждает механизм именования, но не доказывает частоту или конкретный случай `AmneziaVPN 2` в AmneziaVPN. Исходники: [Wintun adapter.c, тег 0.14.1](https://git.zx2c4.com/wintun/tree/api/adapter.c?h=0.14.1).

Отображаемое имя `Alias` и `Description` — отдельные поля. Windows также предоставляет `OperStatus`, флаг `HardwareInterface`, LUID и индекс: [MIB_IF_ROW2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-mib_if_row2). Состояние Up не подтверждает доступность Интернета; наличие строки IPv4 не означает готовый маршрут или адрес.

## Правила

| Условие | Решение |
|---|---|
| `AmneziaVPN` | Допустимое имя |
| `AmneziaVPN 1`, `AmneziaVPN 2`, `amneziavpn 12` | Допустимое имя, регистр сохраняется в выводе |
| N = 1..4294967295, один ASCII-пробел | Допустимый суффикс |
| `+2`, `-2`, `0`, `02`, overflow, не-ASCII цифры, лишние пробелы | Имя отклоняется |
| `AmneziaVPN Backup`, `AmneziaWG`, Ethernet, Wi-Fi | Имя отклоняется |
| Разрешённое имя, но Down, hardware или нет строки AF_INET | Не участвует в выборе |
| Подходящих кандидатов нет | WAITING, без записи |
| Подходящий кандидат один | Работа с его LUID и строкой IPv4 |
| Подходящих кандидатов два или больше | AMBIGUOUS, без записи, код ошибки 1 |
| Ошибка API потенциального кандидата | Прекращение выбора, без записи |

Базовое имя, больший суффикс и порядок перечисления не получают приоритета. Ошибки `ERROR_NOT_FOUND` / `ERROR_FILE_NOT_FOUND` при чтении IPv4 означают отсутствие строки; другие ошибки не скрываются. Физический интерфейс отбрасывается до запроса IPv4. В диагностике для него и других исключённых кандидатов IPv4 помечается `not-queried`.

Для суффикса сначала проверяются ASCII-цифры и отсутствие ведущего нуля, затем положительный UInt32. Одного `parse::<u32>()` недостаточно: он допускает ведущий `+`. См. [Rust FromStr для u32](https://doc.rust-lang.org/std/primitive.u32.html#impl-FromStr-for-u32).

## Запись и гонки

1. Перечислить интерфейсы, прочитать AF_INET для потенциальных кандидатов и выбрать единственного подходящего.
2. Если MTU уже 1280, вернуть PASS без записи.
3. Перед Set заново выполнить полный выбор и чтение. Требовать тот же LUID. При смене цели, исчезновении IPv4/Up или появлении второго подходящего кандидата не писать. Если MTU уже исправлен другим процессом, пропустить запись.
4. Сохранить свежую строку, изменив только `NlMtu=1280`, `SitePrefixLength=0`, `InterfaceIndex=0`; обращаться по LUID. Это соответствует [SetIpInterfaceEntry](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-setipinterfaceentry). Остальные полученные поля сохраняются.
5. Через 350 мс снова выполнить выбор и чтение. Успех коррекции сообщается только для того же LUID и MTU 1280. Исчезновение/замена — WAITING, неоднозначность/ошибка/неверный MTU — FAIL.

Повторная проверка сокращает окно гонки; между последним чтением и Set остаётся неатомарный промежуток. Служба продолжает слушать уведомления и раз в 30 секунд сверяет состояние. Адаптеры, драйверы и VPN не переименовываются и не перезапускаются.

## Диагностика и доверие

Цель хранит фактический alias, LUID, ifIndex, описание и тип. Статус/лог не подставляют базовое имя вместо числового. JSONL-сборщик сохраняет реальный `adapter_alias`, MTU, LUID и индекс; при WAITING/FAIL поля цели null, исходный текст и код сохраняются. Неоднозначность не прекращает наблюдение.

Описание/тип используются для диагностики без жёсткого списка WireGuard/Wintun. Эти строки и флаг hardware не удостоверяют происхождение виртуального устройства. Границы доверия изложены в [SECURITY](SECURITY.md).

## Проверка

Автоматический режим 0.3.0 получил [VERIFIED / PASS на Windows 10 и Windows 11](FIELD_ACCEPTANCE_SUMMARY_2026-11-23.md), где использовался alias без числа. Статус числовых имён и одновременных подходящих интерфейсов остаётся PENDING FIELD TEST; общий успех службы не закрывает эти случаи.

Чистая политика и модель того же пути `apply` тестируются без вызовов реального setter: числовые имена, старый Down, отсутствие IPv4, hardware, неоднозначность, смена LUID/состояния, второй кандидат перед Set, ошибки API, исчезновение при Set/после Set, чужая коррекция и провал верификации. Проверяется сохранение остальных полей строки. PowerShell-тесты проверяют реальные имена, границы UInt32 и продолжение захвата ошибочного статуса.

Результаты сборки: [BUILD_REVIEW](BUILD_REVIEW.md). Полевые T29–T34, реальный split tunneling и восстановление после пересоздания проверяются отдельно по [TESTING](TESTING.md) и [FIELD_TESTS](FIELD_TESTS.md); модель API не выдаётся за E2E.
