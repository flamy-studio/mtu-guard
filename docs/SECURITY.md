# Безопасность и ограничение полномочий

- Изменение IP-параметров через `SetIpInterfaceEntry` требует повышенных прав; Windows-служба работает от `LocalSystem`. Это значимый риск, поэтому код открыт, функциональность строго ограничена изменением MTU на единственном разрешённом Up+IPv4-интерфейсе без признака HardwareInterface. Правила имён и проверок: [NET-002](NET-002.md).
- Установщик копирует EXE в каталог Program Files и устанавливает ACL: SYSTEM и Administrators — полный доступ; Users — только чтение/исполнение. Запуск исполняемого файла из пользовательского Downloads/Temp как LocalSystem **запрещён**.
- Отдельный ACL защищает каталог логов. Никаких пользовательских `.conf`, ключей и токенов в журнал не записывается.
- Клиент не подключается к интернету, не обходит UAC, не устанавливает драйверы, не создаёт прослушивающие TCP-порты и не использует самоподгрузку кода.
- Установка запрашивает согласие пользователя через UAC; Service Control Manager сам запускает сервис при старте Windows.
- Никакой self-update: обновление — новый проверенный EXE и повторная установка. Для релизов MTU Guard публикуются SHA-256; подпись Authenticode желательна перед широким распространением. `CompanyName=Flamy Studio` в ресурсах EXE не является цифровой подписью.
- `status` — read-only и не требует UAC. `fix` — одна привилегированная операция, не более.
- При нескольких подходящих активных интерфейсах — AMBIGUOUS без записи; при отсутствии — WAITING. Неактивные и физические экземпляры не выбираются. Ошибка чтения IPv4 потенциального кандидата прекращает весь выбор, а не скрывает его из списка.
- CRT статически слинкована. Проверка сборки отклоняет обычные и отложенные импорты VC++/UCRT и неизвестных DLL; системные библиотеки Windows остаются обязательной частью ОС.
- SmartScreen и Smart App Control — разные механизмы. У SAC нет исключения для одного приложения. Не рекомендовать отключение защиты или безусловное игнорирование предупреждений; для публичного выпуска нужны проверяемое происхождение, SHA-256 и подпись Authenticode.
- Установщик использует структурированные SCM/CIM-вызовы и проверяет сохранённый путь с кавычками. Установка/удаление отклоняют переход через junction/symlink; рекурсивное удаление ограничено фиксированными каталогами MTU Guard.

## Границы идентификации интерфейса

Допускаются точное базовое имя `AmneziaVPN` и `AmneziaVPN N`, N = 1..4294967295, без знака и ведущих нулей, с ASCII-регистронезависимым сравнением. Перед Set заново проверяются все кандидаты, состояние Up, доступность IPv4 и совпадение LUID с исходной целью. Это сокращает риск гонки, но Windows не предоставляет здесь атомарного сравнения и записи всей выборки.

`HardwareInterface=false` исключает устройства, которые ОС пометила физическими. Alias, описание и тип не удостоверяют производителя: другой виртуальный адаптер с разрешённым именем может пройти эти проверки. Администратор способен переименовать интерфейс и менять сеть без утилиты. Жёсткий список описаний WireGuard/Wintun не введён: он не доказывает принадлежность AmneziaVPN и может отвергать совместимые драйверы. Описание/тип служат диагностике. GUID и LUID идентифицируют экземпляр, но сами по себе не подтверждают его происхождение; LUID заново определяется при пересоздании.

## Что ещё требует полевой приёмки

- Дополнительные сборки Windows и конфигурации за пределами испытанных Windows 10 build 19045 и Windows 11; основной режим 0.3.0 Verified на обеих платформах по [сводке приёмки](FIELD_ACCEPTANCE_SUMMARY_2026-11-23.md). Граничные гонки инициализации и числовые имена требуют отдельных полевых случаев.
- Стойкость к подмене/переименованию другого интерфейса в разрешённое семейство имён. Аттестация происхождения сетевого устройства требует отдельного решения и проверенных данных драйверов; жёсткая привязка к старому GUID помешает пересозданию.
- Проверка сторонних системных фильтров (WinDivert/WFP) не производится: агент исправляет MTU, а не исследует все причины сетевых отказов.
- Полноценная оценка безопасности и репутация подписи бинарника перед публичной публикацией.
